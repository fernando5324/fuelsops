# ADR-019: Identidad de marca centralizada y nombre interno `fuels-ops`

## 1. Contexto

El proyecto creció con la marca escrita en muchos sitios distintos. Una
auditoría previa a esta decisión encontró:

- **Colores duplicados**: `#1B3A6B` en 6 lugares, `#0F172A` y `#64748B` en 5
  cada uno, `#10B981` en 5, `#F47920` en 4. Estaban repartidos entre
  `resources/css/app.css`, `resources/js/app.jsx` (tokens de Ant Design),
  `resources/js/lib/reportCharts.js` (ECharts), `resources/views/app.blade.php`,
  el Blade del PDF y un `style` inline en `SalesReportPdfService`.
- **Valores mágicos de formato**: `'es-ES'` en 12 sitios, `'DD/MM/YYYY'` en 7,
  `S/` en 17 y `' gal'` en 7.
- **Textos repetidos** en `lang/es`: los mismos sustantivos y etiquetas
  definidos a la vez en `order.php`, `pricing.php` y `reports.php`.
- **Nombre del producto** sin definir: el `APP_NAME` era `FuelsOps` en el
  `.env`, y `'Sertoco'` aparecía como fallback en `AuthLayout.jsx`,
  `SalesReportController`, etc.

Además, el proyecto es **multi-tenant** (ADR-008): la misma plataforma sirve a
varias organizaciones (clientes), así que la identidad visual no puede estar
cableada en el código.

---

## 2. Decisión

### 2.1 Nombres: producto vs. cliente

Se separan dos conceptos que estaban mezclados:

- **`fuels-ops`** es el **nombre interno del producto**. Aparece en textos
  internos, en los nombres de archivo exportados y en la documentación. NO se
  muestra al usuario en el panel.
- **El nombre del cliente** es el de la organización activa, y siempre sale de
  la base de datos: `tenants.name`. Es lo que se ve en la cabecera del panel,
  el pie del sidebar, el título del navegador y la página de bienvenida.

El seed actual tiene la organización principal con `tenants.name = 'Sertoco'`,
así que hoy el panel muestra "Sertoco". Mañana, otro cliente verá el suyo sin
tocar código.

### 2.2 Fuente única de la paleta: `config/brand.php`

Toda la identidad visual y las convenciones de formato viven en
`config/brand.php`:

```php
'name'   => env('BRAND_NAME', 'fuels-ops'),
'short'  => env('BRAND_SHORT', 'fuelsops'),
'file_prefix' => env('BRAND_FILE_PREFIX'),   // null = slug del tenant
'logo'   => 'images/logo.png',
'colors' => [ 'primary' => '#1B3A6B', 'accent' => '#F47920', … ],
'format' => [ 'locale' => 'es-PE', 'currency' => 'PEN', 'symbol' => 'S/',
              'date' => 'DD/MM/YYYY', 'gallon' => ' gal' ],
```

### 2.3 Customization por cliente: `tenants.details` (JSON)

La organización puede sobreescribir su paleta y su formato. Se añadió la
columna `tenants.details JSON NULL` (aplicada a la base viva y reflejada en
`docs/02_Database/database.sql`, sección de `tenants`):

```json
{
  "colors": { "primary": "#0A4D8C", "accent": "#FF7A00" },
  "format": { "symbol": "US$", "locale": "en-US" }
}
```

**Prioridad de resolución**: `tenants.details` (BD) **>** `config/brand.php`
(archivo). Un tenant con `details = NULL` se ve igual que el valor por defecto,
por lo que la columna es **aditiva** y se puede migrar cliente por cliente.

La validación es defensiva (`BrandService`):

- Solo se aceptan claves que ya existen en los valores por defecto (un tenant
  no puede inventar tokens).
- Los colores deben cumplir `^#[0-9A-Fa-f]{6}$`; el resto se descarta.
- Solo los colores se normalizan a mayúsculas; los valores de formato se
  respetan tal cual.

## 3. Implementación

### 3.1 Backend

- **`config/brand.php`**: fuente única (nuevo).
- **`config/sertoco.php` → `config/platform.php`**: el archivo llevaba el
  nombre del tenant. Ahora es `platform` y sus env pasaron a
  `PLATFORM_SYSTEM_USER_ID`, `PLATFORM_DEFAULT_TENANT_ID`,
  `PLATFORM_DEFAULT_TENANT_SLUG`, `PLATFORM_BROWSERSHOT_CHROME_PATH`. Se
  actualizaron sus 8 consumidores.
- **`App\Services\BrandService`**: resuelve tenant + paleta + formato en un
  **singleton** (`AppServiceProvider`), de modo que el tenant se consulta una
  sola vez por petición aunque lo pidan la prop de Inertia, el `<style>` del
  blade y el `ConfigProvider` del front. Expone `cssVariables()` (mapa de
  `--color-*`) y `toArray()` (prop `brand`).
- **`HandleInertiaRequests`**: la prop `tenant` se arma con
  `BrandService::tenantProp()` y se añade la prop **`brand`** (producto,
  cliente, slug, logo, colores, formato).
- **`resources/views/app.blade.php`**: imprime
  `<style>:root{--color-*: …}</style>` desde `cssVariables()` en el primer
  paint, y el `<title>` usa el nombre del cliente con fallback
  `config('brand.name')`.
- **`app/Models/Tenant`**: `details` en `fillable` con cast `array`.

### 3.2 Frontend

- **`resources/js/lib/brand.js`**: `FALLBACK_BRAND`, `brandColors()`,
  `brandFormat()`, `useBrand()`, `cssColor()` y `brandThemeTokens()`. No hay
  ningún color hardcodeado: si falta la prop, cae a `FALLBACK_BRAND`.
- **`resources/js/lib/format.js`**: `locale()`, `currency()`, `symbol()`,
  `dateFormat()`, `gallonUnit()`, `formatNumber()`, `formatGallons()`.
- **`resources/js/app.jsx`**: el `ConfigProvider` de Ant Design deriva sus
  tokens de `brandThemeTokens()` y la barra de progreso de Inertia usa
  `cssColor('--color-primary')`.
- **`resources/css/app.css`**: sin ningún hex. El bloque `:root` se eliminó
  (lo genera el servidor) y los literales que quedaban se sustituyeron por
  `var(--color-*)`.
- **`resources/js/lib/reportCharts.js`**: `COLORS` y `PRODUCT_COLORS` desde
  `brandColors()`; tooltips con `locale()` y `dateFormat()`.
- **`resources/js/lib/money.js`**, **`dates.js`**, **`files.js`**: usan el
  locale/símbolo/formato de la plataforma en vez de literales.
- **PDF (ADR-018)**: el Blade `reports/sales-pdf.blade.php` toma la paleta de
  `$colors` y el símbolo de `$format`; `SalesReportPdfService` inyecta esos
  valores y arma el nombre de archivo con `BrandService::filePrefix()`.

### 3.3 Deduplicación de textos (`lang/es`)

Los sustantivos y etiquetas que eran **idénticos** entre módulos se movieron a
`lang/es/common.php` y los módulos los referencian con `__('common.…')`:

`plant`, `product`, `wholesaler`, `gallons`, `margin`, `customer`, `driver`,
`vehicle`, `pending`, `status` (ya existía), `total_gallons`, `sales_report`.

Los textos que solo se parecen (p. ej. "Total galones" vs "Total de galones")
siguen en su archivo de módulo. El catálogo de bancos de depósitos se movió de
`OrderDeposits.jsx` a `lang/es/banks.php`.

### 3.4 Defectos corregidos

1. **Margen `invalid_margin` ambiguo**: existían dos claves
   `pricing.invalid_margin` (sueltas) y `pricing.errors.invalid_margin`; la
   primera no la usaba nadie. Se eliminó la suelta y quedó la que resuelve
   `__("pricing.errors.{$code}")`.
2. **`pricing.no_active_configuration` inexistente**: `PriceApiController` la
   usaba en 4 puntos, así que el usuario veía la clave cruda. Ahora apunta a
   `pricing.errors.no_active_configuration`.
3. **`es-ES` mezclado con `es-PE`**: las cantidades se formateaban `es-ES` y el
   dinero `es-PE`. Se unificó al locale de la plataforma (`es-PE`), de modo que
   separador decimal y de miles son consistentes. Cambio visible: `1.234,5` →
   `1,234.5`.
4. **`common.brand` duplicado**: existía `'brand' => 'Sertoco'` y, más abajo,
   `'brand' => config('brand.name', 'fuels-ops')`. PHP se queda con el último,
   pero el primero era engañoso: eliminado.
5. **`strtoupper` sobre el formato**: `BrandService::merge()` ponía en
   mayúsculas también los valores de formato de un tenant; ahora solo aplica a
   colores.

## 4. Formato y compatibilidad

- El prefijo de los archivos exportados sigue siendo el **slug del tenant**
  (`sertoco_precios_…`), así que las verificaciones existentes
  (`verify_sales_pdf.php`, `verify_pricing_export.php`) no cambian de
  expectativa.
- El `<title>` sigue reflejando `tenants.name` (`verify_tenant_title.php`).
- No hay migraciones Laravel: el cambio de esquema (`tenants.details`) se
  aplicó directo a la base viva y se reflejó en `docs/02_Database/database.sql`,
  `SEEDS.sql` y `database_design.md`.

---

## 5. Limitaciones conocidas

- **Logo por cliente**: `tenants.logo_media_file_id` existe, pero la única
  ruta de media (`media.download`) sirve con
  `Content-Disposition: attachment`, que un `<img>` no muestra.
  `BrandService::logoUrl()` devuelve hoy el logo de la plataforma
  (`config('brand.logo')`); queda pendiente una ruta de media **en línea** para
  poder pintar el logo de cada organización.
- **Bundle del PDF**: `lib/brand.js` importa `@inertiajs/react`. Como el
  runtime del PDF corre fuera de Inertia, `vite.pdf.config.js` aliasa
  `@inertiajs/react` a `resources/js/pdf/inertia-stub.js` (y declara el alias
  `@`). Así el PDF usa `FALLBACK_BRAND` sin arrastrar React.

## 6. Verificación

- `php -l` de los archivos PHP tocados.
- Build del front (`vite build`) y del runtime del PDF
  (`vite build --config vite.pdf.config.js`).
- E2E por HTTP contra el host virtual (`http://sertocoplatform`):
  `verify_tenant_title.php` y, para la marca, un `verify_brand_palette.php`
  (prioridad BD > archivo, `:root` renderizado, prop `brand`, tenant sin
  `details`).
- `verify_sales_pdf.php` y `sales_pdf_consistency.php` sin regresiones
  (nombre de archivo y contenido del PDF).
