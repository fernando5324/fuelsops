# ADR-064: Organización de controladores y servicios por módulo

**Estado:** Aceptado
**Fecha:** 2026-09-01

## Contexto

La plataforma contiene múltiples módulos principales como productos, artículos, páginas, servicios, usuarios, etc.

Inicialmente se consideró una estructura global con carpetas separadas para `Controllers`, `Apis`, `Services`, `Actions`, `Requests`, entre otras. Sin embargo, a medida que el sistema crezca, esta organización puede dificultar la localización de todos los archivos relacionados con un mismo módulo.

También se evaluó una arquitectura altamente fragmentada basada en múltiples clases `Action` para separar cada operación individual. Se considera que este nivel de fragmentación no es necesario para el proyecto y puede generar una cantidad excesiva de archivos y mayor complejidad de mantenimiento.

## Decisión

Se utilizará una **organización por módulo** dentro de `Platform`.

Cada módulo principal tendrá su propia carpeta y contendrá únicamente las clases necesarias para su funcionamiento.

La estructura base será:

```text
app/
└── Http/
    └── Controllers/
        ├── Platform/
        │   ├── Products/
        │   │   ├── ProductController.php
        │   │   ├── ProductApiController.php
        │   │   └── ProductService.php
        │   │
        │   ├── Articles/
        │   │   ├── ArticleController.php
        │   │   ├── ArticleApiController.php
        │   │   └── ArticleService.php
        │   │
        │   ├── Pages/
        │   │   ├── PageController.php
        │   │   ├── PageApiController.php
        │   │   └── PageService.php
        │   │
        │   └── ...
        │
        └── Web/
            └── ...
```

### Responsabilidad de cada archivo

#### `*Controller.php`

Se encargará principalmente de la navegación y renderizado de las interfaces del `Platform`.

Ejemplos:

```text
GET /platform/products
GET /platform/products/create
GET /platform/products/{product}/edit
```
Ejemplo:
```
public function index(Request $request): Response
    {
        $this->rbacService->authorize('articles.view');

        $tenantId = ActiveTenant::id();

        if (! $tenantId) {
            return Inertia::render('Articles/Index', [
                'articles' => [],
                'filters' => [],
                'categories' => [],
            ]);
        }

        $search = trim((string) $request->query('search', ''));

        $status = $request->query('status');
        if (! in_array($status, ['draft', 'published', 'archived'], true)) {
            $status = null;
        }

        $categoryId = filter_var($request->query('category_id'), FILTER_VALIDATE_INT);
        $categoryId = $categoryId ?: null;

        $articles = Article::active()
            ->where('tenant_id', $tenantId)
            ->when($search !== '', function ($query) use ($search) {
                $query->whereHas('translation', function ($q) use ($search) {
                    $q->where('title', 'like', '%'.$search.'%');
                });
            })
            ->when($status, function ($query) use ($status) {
                $query->where('status', $status);
            })
            ->when($categoryId, function ($query) use ($categoryId, $tenantId) {
                $query->whereHas('categories', function ($q) use ($categoryId, $tenantId) {
                    $q->where('categories.tenant_id', $tenantId)
                        ->where('categories.id', $categoryId);
                });
            })
            ->with('translation', 'categories.translation', 'coverMedia')
            ->orderByDesc('id')
            ->paginate(10)
            ->withQueryString();

        $articles->through(function (Article $article) {
            return [
                'id' => $article->id,
                'title' => $article->translation?->title,
                'slug' => $article->translation?->slug,
                'status' => $article->status,
                'is_featured' => $article->is_featured,
                'author_name' => $article->author_name,
                'cover' => $this->mediaService->urlFor($article->coverMedia),
                'published_at' => $article->published_at?->format('Y-m-d'),
                'categories' => $article->categories
                    ->map(fn ($category) => $category->translation?->name)
                    ->filter()
                    ->values(),
            ];
        });

        return Inertia::render('Articles/Index', [
            'articles' => $articles,
            'filters' => [
                'search' => $search,
                'status' => $status,
                'category_id' => $categoryId,
            ],
            'categories' => $this->availableCategories($tenantId),
        ]);
    }

    /**
     * Return the categories available for the active tenant (for the form).
     */
    protected function availableCategories(int $tenantId)
    {
        return Category::active()
            ->where('tenant_id', $tenantId)
            ->where('type', 'article')
            ->with('translation')
            ->orderBy('sort_order')
            ->get()
            ->map(fn (Category $category) => [
                'id' => $category->id,
                'name' => $category->translation?->name,
            ]);
    }

    /**
     * Show the form for creating a new article.
     */
    public function create(): Response
    {
        $this->rbacService->authorize('articles.create');

        $tenantId = ActiveTenant::id();

        abort_unless($tenantId, 403);

        return Inertia::render('Articles/Form', [
            'article' => null,
            'categories' => $this->availableCategories($tenantId),
        ]);
    }

    /**
     * Show the form for editing the specified article.
     */
    public function edit(Article $article): Response
    {
        $this->rbacService->authorize('articles.update');

        $tenantId = ActiveTenant::id();

        abort_unless($tenantId && $article->tenant_id === $tenantId, 403);

        $article->load('translation', 'categories', 'coverMedia');

        return Inertia::render('Articles/Form', [
            'article' => [
                'id' => $article->id,
                'title' => $article->translation?->title,
                'slug' => $article->translation?->slug,
                'summary' => $article->translation?->summary,
                'content' => $article->translation?->content_json,
                'cover' => [
                    'url' => $this->mediaService->urlFor($article->coverMedia),
                    'original_name' => $article->coverMedia?->original_name,
                ],
                'author_name' => $article->author_name,
                'status' => $article->status,
                'is_featured' => $article->is_featured,
                'published_at' => $article->published_at?->format('Y-m-d'),
                'show_cover' => $article->show_cover,
                'show_author' => $article->show_author,
                'show_date' => $article->show_date,
                'show_share' => $article->show_share,
                'show_related' => $article->show_related,
                'categories' => $article->categories->pluck('id')->all(),
                'seo' => $this->articleService->seoFor($article, $tenantId),
            ],
            'categories' => $this->availableCategories($tenantId),
        ]);
    }
```

Su responsabilidad principal será preparar y devolver las vistas o páginas de Inertia.

#### `*ApiController.php`

Será el principal controlador para las operaciones del módulo.

Aquí se concentrará la mayoría de las acciones CRUD y operaciones HTTP relacionadas con el módulo:

```text
POST   /api/platform/products
PUT    /api/platform/products/{product}
DELETE /api/platform/products/{product}
```

El `ApiController` será responsable de:

* recibir la petición HTTP;
* utilizar Form Requests cuando sea necesario;
* autorizar la operación;
* llamar al modelo o servicio correspondiente;
* devolver la respuesta HTTP.

No deberá convertirse en el lugar donde se acumule toda la lógica de negocio compleja.

#### `*Service.php`

Se utilizará cuando una operación tenga suficiente complejidad como para justificar extraerla del controlador.

Por ejemplo, una creación de producto que implique:

```text
Producto
 ├── Traducciones
 ├── Categorías
 ├── Media
 └── otras relaciones
```

El servicio podrá coordinar estas operaciones y manejar transacciones o reglas de negocio.

No será obligatorio crear un servicio para operaciones CRUD simples.

## No se utilizará una estructura basada obligatoriamente en Actions

No se crearán clases como:

```text
CreateProduct.php
UpdateProduct.php
DeleteProduct.php
AttachProductCategory.php
CreateProductTranslation.php
...
```

para cada operación individual.

Esta fragmentación solo se introducirá posteriormente si aparece una necesidad real que justifique separar una operación compleja o reutilizable.

La prioridad es mantener una arquitectura organizada pero sencilla de mantener.

## Principio de responsabilidad

La separación será:

```text
Controller
    ↓
Navegación / Inertia

ApiController
    ↓
HTTP / CRUD / coordinación

Service
    ↓
Lógica de negocio compleja
```

No se pretende que cada archivo tenga una única función extremadamente específica. Se busca una separación clara de responsabilidades sin generar una cantidad innecesaria de clases.

## Criterio para utilizar Services

Una operación puede permanecer en el `ApiController` cuando sea sencilla, por ejemplo:

```php
$product->update($request->validated());
```

Se considerará utilizar `ProductService` cuando la operación implique múltiples pasos, entidades, relaciones, transacciones, reglas de negocio o procesos que convenga reutilizar.

## Justificación

Esta estructura combina dos objetivos:

1. **Organización por módulo:** todos los archivos relacionados con una funcionalidad permanecen juntos.
2. **Simplicidad:** se evita crear archivos y capas innecesarias para operaciones sencillas.

De esta manera, el proyecto puede crecer desde un CRUD relativamente simple hasta operaciones de negocio más complejas sin obligar desde el inicio a adoptar una arquitectura excesivamente fragmentada.

## Consecuencia

Un nuevo módulo deberá seguir inicialmente esta estructura:

```text
Module/
├── ModuleController.php
└── ModuleApiController.php
```

El `ModuleService.php` se añadirá únicamente cuando exista una necesidad concreta:

```text
Module/
├── ModuleController.php
├── ModuleApiController.php
└── ModuleService.php
```

La arquitectura podrá evolucionar posteriormente si un módulo alcanza un nivel de complejidad que justifique introducir `Actions`, `Repositories` u otras abstracciones, pero estas no serán obligatorias por defecto.
